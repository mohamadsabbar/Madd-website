# منصة أوليفيا — إدارة مشتركي ISP وربط MikroTik

نظام ويب مبني على **Laravel** + **MySQL** مع واجهة إدارة (لوحة تحكم زجاجية) وبوابة وكلاء، وتكامل **RouterOS API** لحسابات **PPPoE**، وإرسال **SMS** (مزوّد HTD وغيره عبر الإعدادات).

---

## المتطلبات

- PHP 8.2+ مع الامتدادات المعتادة لـ Laravel (`pdo_mysql`, `mbstring`, `openssl`, `sockets` لاتصال MikroTik API إن لزم)
- Composer
- MySQL/MariaDB
- Node/npm اختياري لأصول الواجهة إن وُجدت

---

## التثبيت والتشغيل

1. انسخ `.env.example` إلى `.env` واضبط:
   - `APP_URL`
   - `DB_*`
   - مفاتيح **SMS** إن أردت الإرسال الفعلي (انظر قسم [SMS](#sms-والفوترة))
2. نفّذ:
   ```bash
   composer install
   php artisan key:generate
   php artisan migrate --seed
   php artisan serve
   ```
3. بعد أي تعديل على `.env`:
   ```bash
   php artisan config:clear
   ```

### صفحة الشركة على الرئيسية `/`

- **الزائر** يفتح `https://نطاقك.com/` فيرى صفحة شركتك فقط (بدون أزرار دخول أو وكلاء).
- **الوكلاء والإدارة** يستخدمون **`https://نطاقك.com/login`** — يمكنك إرسال هذا الرابط للوكلاء فقط.
- إن كان لديكم روابط قديمة لـ `/company` فهي تُحوَّل تلقائياً إلى `/` (301).
- القالب: **`resources/views/public/company-home.blade.php`** — الشعار من `public/brand/` إن وُجد.
- الإعدادات: **`config/landing.php`** ويمكن من `.env`:
  - `LANDING_COMPANY_NAME`، `LANDING_HEADLINE`، `LANDING_LEAD`، `LANDING_EXTRA`
  - `LANDING_FEATURES` — أسطر مفصولة بـ `|`
  - `LANDING_PHONE`، `LANDING_EMAIL`، `LANDING_ADDRESS` — قسم «تواصل معنا»
- بعد تغيير النصوص: `php artisan config:clear`.

## المشتركين — التمديد و SMS

### التمديد من واجهة التفاصيل

- من صفحة **تفاصيل المشترك** (`/admin/subscribers/{id}`) يوجد قسم **«تمديد الاشتراك»**.
- **الحد الأدنى 3 أيام**، **الحد الأقصى 365 يوماً**.
- المنطق البرمجي (`AdminSubscriberController@extendSubscription`):
  - يُحدَّد **تاريخ الأساس** = الأكبر بين **تاريخ انتهاء الاشتراك الحالي** و**اليوم** (إن كان الاشتراك منتهيًا يُحسب من اليوم).
  - **تاريخ الانتهاء الجديد** = الأساس + عدد الأيام المختار.
  - إذا أصبح الاشتراك ساريًا: `status = active` و` suspended_at = null`.
  - إذا كان المشترك **معلّقًا** سابقًا: يُستدعى **تفعيل PPPoE** على المايكروتيك (`enablePppoeUser`) عند الإمكان.

### رسالة SMS بعد التمديد

- إذا وُجد **رقم هاتف** للمشترك و**SMS مفعّل** في الإعدادات، تُرسل رسالة بعد نجاح التمديد.
- القالب الافتراضي في `config/billing.php` تحت `sms_messages.extend` (يمكن تجاوزه بـ `.env`):

  `BILLING_SMS_TEMPLATE_EXTEND`

- المتغيرات المتاحة في القالب: `{days}` `{end_date}` `{name}` `{company}`  
  الافتراضي الحالي لا يضم اسم الشركة في البداية ولا اسم المشترك؛ النص مثال:

  `تم تمديد خطك {days} أيام حتى {end_date}.`

- الخدمة: `App\Services\BillingSmsService`  
  - إذا كان **رابط GET** طويلاً جدًا (رسالة عربية)، يُحوَّل الإرسال تلقائيًا إلى **POST** (نفس الحقول).  
  - يمكن فرض POST دائمًا: `BILLING_SMS_FORCE_POST=true`  
  - بعد تغيير `.env`: `php artisan config:clear`

---

### حذف المشترك

من زر **«حذف المشترك»** في صفحة تفاصيل المشترك (`/admin/subscribers/{id}`) — تظهر نافذة تأكيد فيها خياران:

1. **حذف من البرنامج فقط** — يُحذف المشترك وفواتيره ودفعاته وحساب تطبيق العميل من قاعدة البيانات، **لكن يبقى سر PPPoE موجوداً على المايكروتيك** (يستطيع العميل الاتصال إن لم يُعطَّل يدوياً).
2. **حذف من البرنامج والمايكروتيك** — حذف كامل: يُفصل المشترك من الجلسة النشطة (إن وُجدت) ثم يُزال سر PPPoE من الراوتر، ثم يُحذف من قاعدة البيانات.

ميزات الأمان:

- يجب كتابة **اسم PPPoE** في خانة التأكيد لتفادي الحذف بالخطأ.
- إذا فشل حذف السر من المايكروتيك في وضع «كامل»، تُلغى العملية بأكملها ولا يُحذف من قاعدة البيانات.
- الفواتير والدفعات وجلسات الراوتر وطلبات التجديد تُحذف تلقائياً عبر `cascadeOnDelete` في الجداول.
- لقطات الترافيك (`subscriber_traffic_snapshots`) تبقى تاريخياً مع `subscriber_id = NULL`.
- العملية مسجَّلة في `storage/logs/laravel.log` (تشمل المسؤول الذي نفّذها ووضع الحذف).

المنطق البرمجي: `AdminSubscriberController@destroy` + `MikrotikService::deletePppoeUser`.

## سجل العمليات الداخلي

صفحة **`/admin/activity`** (رابط في الشريط الجانبي: «سجل العمليات») تعرض كل ما يحدث في النظام للمراقبة والتدقيق.

### الإحصائيات اليومية في الأعلى
- إجمالي مبلغ الدفعات المسجَّلة اليوم وعدد العمليات.
- عدد المشتركين الذين عُلِّقوا اليوم (يدوي + تلقائي).
- عدد رسائل SMS التي أُرسلت اليوم بنجاح، وعدد التي فشلت.
- عدد عمليات التمديد اليوم وإجمالي العمليات.

### الفلاتر
- **الفئة**: المشتركين / الاشتراكات / الدفعات / الرسائل / مهام مجدولة.
- **النوع التفصيلي**: قائمة بكل أنواع الأحداث الموجودة فعلياً.
- **الخطورة**: نجاح / معلومات / تنبيه / خطأ.
- **نطاق تاريخي** (من/إلى).
- **بحث نصي** في الرسالة، اسم المشترك، الهاتف، اسم المنفّذ.

### الأحداث المسجَّلة حالياً

| النوع | متى يُسجَّل |
|------|---------|
| `subscriber.created` | إضافة مشترك جديد من الإدارة |
| `subscriber.updated` | تعديل بيانات مشترك |
| `subscriber.extended` | تمديد اشتراك (مع رسالة SMS) |
| `subscriber.deleted` | حذف مشترك (يتضمن وضع الحذف: program/all) |
| `subscriber.suspended` | تعليق يدوي عبر API |
| `subscriber.reconnected` | إعادة وصل يدوي عبر API |
| `subscriber.renewed` | تجديد عبر `/api/admin/.../renew` |
| `subscriber.auto_suspended_expired` | تعليق تلقائي عند انتهاء الاشتراك (Scheduler) |
| `subscriber.auto_suspended_unpaid` | قطع تلقائي يوم الفوترة لغير المسدِّدين |
| `subscription.renewed_by_agent` | تجديد عبر بوابة الوكيل (مع المبلغ والوكيل) |
| `payment.received` | استلام دفعة على فاتورة (مع المبلغ والطريقة) |
| `sms.bulk` | إرسال رسائل من `/admin/sms` (نجاح/فشل + قائمة الفشل) |
| `sms.reminder_batch` | تذكيرات الفوترة المجدولة قبل يوم الاستحقاق |
| `system.auto_suspend_expired` / `system.auto_suspend_unpaid` | تشغيل المهام المجدولة (ملخص) |

### كل سطر يحتوي
- وقت الحدث، نوعه، رسالة عربية واضحة، اسم المشترك المتأثر (مع رابط لصفحته)، اسم المنفّذ ودوره، الحالة (نجاح/تنبيه/خطأ)، والمبلغ إن وُجد.
- زر **«تفاصيل تقنية»** يكشف JSON بالميتاداتا الكاملة (معرّف الفاتورة، أسباب الفشل، طريقة الدفع، إلخ).
- في رسائل SMS الفاشلة: قائمة بأسماء وأرقام المشتركين الذين فشل الإرسال إليهم وسبب الفشل من المزوّد.

### المنطق البرمجي
- جدول قاعدة البيانات: `activity_logs` (انظر migration `2026_05_03_200000_create_activity_logs_table`).
- الموديل: `App\Models\ActivityLog`.
- الخدمة: `App\Services\ActivityLogger` — `::log()` / `::success()` / `::warning()` / `::error()`.
- لا يرمي استثناءات للحفاظ على المسار الرئيسي (failure-safe).
- يلتقط تلقائياً المنفّذ من `auth()->user()` (أو `null` للمهام المجدولة) و IP الطلب إن توفّر.

## SMS والفوترة

إعدادات أساسية في `.env` (انظر أيضًا `config/billing.php`):

| المتغير | المعنى |
|---------|--------|
| `BILLING_SMS_ENABLED` | تفعيل الإرسال الفعلي |
| `BILLING_SMS_API_URL` | رابط API (مثال HTD: `http://sms.htd.ps/API/SendSMS.aspx`) |
| `BILLING_SMS_HTTP_METHOD` | غالبًا `GET` أو `POST` حسب المزوّد |
| `BILLING_SMS_API_KEY` | عند HTD: قيمة `id` في الرابط |
| `BILLING_SMS_SENDER` | اسم المرسل المعتمد لدى المزوّد |
| `BILLING_SMS_PHONE_FORMAT` | `ps970`: تحويل أرقام محلية إلى صيغة `970…` |
| `BILLING_SMS_FORCE_POST` | إجبار POST |
| `BILLING_SMS_MAX_GET_URL_LENGTH` | حد طول رابط GET قبل التحويل لـ POST |
| `BILLING_COMPANY_NAME` | يُستخدم في قوالب أخرى (مثل التذكيرات) |

لوحة **«SMS»** في الإدارة: `/admin/sms` — إرسال لجميع المشتركين / لمشترك / لراوتر محدد.

تذكيرات الفوترة الآلية: أمر مجدول `SendBillingSmsReminders` (راجع `routes/console.php` و`config/billing.php`).

## واجهة API (Sanctum)

أمثلة (تفصيل المسارات في `routes/api.php`):

- `POST /api/login` — بريد **أو** هاتف (للعميل: `phone` + `password`؛ للإدارة/الوكيل: `email` + `password`)
- موارد الإدارة: `api/admin/...` (مشتركين، باقات، فواتير، وكلاء، تعليق/تفعيل…)
- وكيل: بحث، تجديد، تحصيل…
- **عميل (تطبيق Flutter):** يُنشأ تلقائياً مع المشترك: نفس **رقم الهاتف** وكلمة **`SUBSCRIBER_PORTAL_DEFAULT_PASSWORD`** (افتراضي `100200300` في `config/subscriber_portal.php`). يتطلب ربطاً بسجل مشترك (`subscribers.user_id`):
  - `GET /api/customer/subscription` — حالة الاشتراك، الباقة، السرعة، الراوتر، انتهاء الصلاحية، طلب تمديد معلّق.
  - `POST /api/customer/renewal-request` — جسم اختياري `{ "note": "..." }` لتسجيل طلب تمديد (جدول `customer_renewal_requests`).

### تطبيق العملاء (Flutter)

المجلد: `olivia_customer/`. **تسجيل الدخول:** رقم الهاتف كما في سجل المشترك + كلمة المرور الافتراضية (أو التي تضبطها في `.env`). للمشتركين القدامى بدون حساب: `php artisan subscribers:sync-portal-users`. **عنوان الـ API على الهاتف:** من شاشة الدخول اضغط أيقونة الشبكة واكتب **IP جهاز الكمبيوتر** الذي يشغّل Laravel (مثل `192.168.0.105:8000`) — لا تستخدم عادةً `192.168.0.1` (غالباً الراوتر). شغّل الخادم: `php artisan serve --host=0.0.0.0 --port=8000`. محاكي أندرويد: `10.0.2.2:8000`. يمكن أيضاً `--dart-define=API_BASE=...` عند البناء.
